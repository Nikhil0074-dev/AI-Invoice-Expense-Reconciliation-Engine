# Testing

```bash
cd backend && pip install -r requirements-dev.txt && python -m pytest -q      # 113 tests
cd frontend && npm ci && npm run typecheck && npm test && npm run build       # 21 tests
```
Backend tests use a temporary SQLite database, inline job processing and synthetic documents generated by
`backend/tests/fixtures/docs.py` (ReportLab PDFs, Pillow-rendered receipts — real Tesseract OCR runs on them).

| Suite | Covers |
|---|---|
| `unit/test_normalize` | amounts (1,234.56 / 1.234,56 / lakh / parentheses), dates (ambiguity, German/French months), currencies, vendor normalisation |
| `unit/test_parser_validators` | English & German invoices, table-style layouts, CGST+SGST, ambiguous date, missing fields never guessed, arithmetic validation |
| `unit/test_matching` | spec examples A–D, date decay, currency mismatch, partial/split, reference signal, ranking |
| `unit/test_export_security_misc` | CSV injection, quoting, hashing/JWT, rate limiter, magic bytes, native-PDF-skips-OCR, Tesseract on PNG and scanned PDF, corrupt files |
| `integration/test_auth_and_isolation` | auth, reset flow, 401/403/404 isolation on every resource, role matrix, last-admin rule, settings validation |
| `integration/test_documents_and_review` | extraction pipeline, corrections + audit, backend validation, verify gates, upload validation (413/400), failure + retry + idempotency, search/filter/paginate |
| `integration/test_duplicates_and_import` | exact/likely/possible/not-duplicate, review flow, archive, CSV mapping/sign conventions, repeat-import protection, European formats, dry run |
| `integration/test_reconciliation_exports` | suggest/confirm, split & partial payments, over-allocation, currency rules, reject/unlink, protection of reconciled invoices, exports (all 6 types), dashboard, **end-to-end acceptance workflow** |
| `integration/test_migrations` | `alembic upgrade head`, `alembic check` (no drift), downgrade |

## Measuring accuracy (do this before trusting results)
The fixtures verify *behaviour*, not *accuracy*. To report metrics, build a labelled set (documents + verified field values +
true invoice↔transaction pairs), keep a held-out split, and compute field accuracy, total accuracy, match precision/recall and
review rate. No accuracy figure is claimed by this project.
